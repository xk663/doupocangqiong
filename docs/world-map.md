# 山河行旅：开放探索地图

## 本轮交付

保留静态 HTML/JavaScript 架构，入口为主游戏 `index.html` 的「大世界」，独立演示为 `map.html`。无需安装构建依赖。通过 HTTP 服务器打开，例如在项目根目录运行 `python -m http.server 8086`。独立演示采用单独的 `doupo-world-demo-v1` 存档键，不修改主游戏角色。

四幅1536×1024生图底图：大陆总览、乌坦城、青山镇、石漠城。以青绿山水、绢纸和暖金为基础；固定斜俯视，允许拖动、鼠标滚轮、双指缩放、WASD/方向键步行及按钮定位。文字、人物标记、路线、选中态和玩家指示器由渲染层叠加。图中装饰人物属于插画；可交互人物另有标记和目录。

共79个节点（62个有小说章节依据的地点、17个原创互动点）、79条游戏道路或入口连接。双帝山为终局时间层，保留资料但不连入当前旅行。三处出发地有本地互动图；其他地点共享大陆总览和规则，尚未逐城绘制街区。6名原创地方人物提供日夜位置、打听、补给、委托及进入自由聊天的入口。

## 模块和状态

| 模块 | 职责 |
| --- | --- |
| `assets/data/world.json` | 可编辑的地点、道路、场景、NPC和交易目录 |
| `world-data.js` | 同一目录的静态浏览器/Node版本，支持普通静态部署 |
| `world-core.js` | 纯规则：寻路、门槛、资源、24小时制时间、日夜人物位置、交易、委托、确定性事件、探索线索、上下文和行动建议校验 |
| `world-bridge.js` | 主游戏状态适配、行动提交、失败回滚、存档与回溯、聊天草稿、建议确认；独立演示可替换适配器 |
| `world-renderer.js` | PixiJS 8.22.0画面与手势；图形不可用时使用DOM底图与可点击地点 |
| `world-ui.js` / `world-map.css` | 层级切换、已知地点搜索、旅行预算、人物、商店、委托、手札及手机布局 |
| `world-standalone.js` | 独立演示适配器、单独保存与对话入口演示 |

一次地图行动经过：读取并校验当前状态 → 纯规则计算完整下一状态 → 记录行动前快照 → 提交角色/物资/金币/时间/世界/任务 → 原子保存运行时信封 → 刷新视图。保存失败则还原内存与新增快照。LLM正在推演时不接受地图结算。

探索进度保存在 `player.exploration`，版本1，含当前位置、发现与到访地点、精力、游戏分钟、种子、信任、委托、事件标志及最多60条手札。行囊、金币和世界时间仍由主游戏原有字段管理，不另造一套余额。既有v2完整存档与回溯自动携带地图进度。未知地图版本给出错误，不静默丢弃进度。

旅行先在已知节点与满足境界条件的连接中寻路，再显示小时、金币、干粮、水囊与精力。点击地点、人物或道路会直接开始动态行走，本地区使用步行路径，跨区域使用既有旅行规则；到达才结算，途中可停步。化翼飞行需斗王；传送与虫洞不获得飞行折扣。路线随机小事根据存档种子和路线/日期决定，不在重画时重新抽取。首次野外探索可得基础材料，重复探索有冷却且不反复生成首次奖励；发现入口也不等于获得异火或秘境宝物。

地方委托只有接取、满足条件、返回委托人并交付后才发报酬，同一存档不能重复领取。旧任务页不能直接绕过地图交付。角色选择休整后才推进日夜，NPC按日间/夜间锚点切换；这不是完整的自主NPC生活模拟。人物互动按角色的实际步行位置检查距离。

## 聊天衔接

自由交谈会切回主聊天并填写草稿，玩家发送后才调用已有模型配置。注入当前位置、资源、附近可接触人物、最近5条手札及有限已知地点；不将秘密地点全部塞入上下文。地图实际记录优先于叙事推断。

非纯文本模式可返回一个 `<world_action>{"type":"travel","targetId":"qingshan","mode":"walk"}</world_action>` 建议；还支持 `explore`、`rest`、`talk`。协议只接受白名单、已知地点/附近人物，额外奖励字段无效。正文移除控制标签。建议不自动执行，玩家进入地图确认后再次检查实际成本。地图行动、回溯、换会话或重新创角会清除或使旧建议失效。纯文本模式不要求输出控制标签。

聊天重演保留其间已执行的地图位置、行囊与探索记录；若玩家有意撤销旅行，使用时空回溯。地图并未把模型任意描述的战斗、突破或获得异火直接当作已结算事实。

## 小说依据与设计边界

有章节证据的地点来自此前整理的小说地图资料，每个条目保留章节号与标题。美术画面、具体坐标、可通行连接、旅行时长、费用、补给消耗、原创人物和地方委托属于游戏设计值，不宣称是作者精确地图或原著数值。独立空间与地底入口区分层级；图中投影仅用于操作，不意味着它们在地表实际相邻。地方原创人物不冒充药老、薰儿等原著角色。

图片由本轮原生生图工具制作，提示词见 `world-map-art.json`。原始图片保留在生成目录，项目内为副本。PixiJS以本地UMD文件加载，保留MIT许可证，无运行时CDN依赖；地图底图按场景加载，不一次载入四张图。

## 美术与Tiled工作流

`maps/authoring` 中的四份 `.tmj` 可直接用Tiled打开。第一层为无字底图，第二层为地点锚点，`worldId` 为稳定标识，不能把名称变化当成新地点。NPC活动表和道路关系由目录维护，移动图面锚点不改变规则。不要用重新生成四份作者文件覆盖尚未导入的手工编辑。

```sh
# 从当前目录导出四份Tiled作者文件；编辑前先保留已有修改
node scripts/world-maps.cjs export
# 校验Tiled文件或Tiled导出的JSON，不修改运行目录
node scripts/world-maps.cjs check maps/authoring/wutan.tmj
# 将已编辑的锚点导入JSON目录并同步浏览器数据
node scripts/world-maps.cjs import maps/authoring/wutan.tmj
# 若手工编辑了JSON的道路、人物或描述，同步浏览器文件
node scripts/world-maps.cjs sync
node --test tests/*.test.cjs
```

导入只接受已知ID、匹配场景和合法范围的有限坐标，不导入作者文件中的任意脚本。本轮实际用已安装Tiled命令行导出乌坦城并校验8个锚点，而非只放置软件图标。LDtk/Azgaar/Figma未加入本次运行依赖，当前图面使用Tiled即可维护，避免同时维护多套坐标来源。

## 性能与兼容

PixiJS按首次进入地图加载；按场景加载图片，缓存最多两张底图。分辨率上限1.5，动画30帧上限，隐藏视图/标签暂停，减少动态效果设置关闭动画。手机布局上方地图、下方可滚动行动面板，目录可通过键盘访问。URL加 `?mapRenderer=lightweight` 可主动使用轻量DOM渲染，旅行与存档规则保持相同。

本轮未测所有低端移动设备、触控硬件或浏览器，不能把桌面窄视口检查等同于真机性能结论。细化全部大陆城镇、战斗/成长规则、势力领地动态变化、原著人物任务链、大规模NPC自主行为仍需要后续内容制作；当前交付是可游玩的第一版与可扩展的互动底座。
