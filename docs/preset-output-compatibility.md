# 预设正文格式与显示兼容

## 修复的缺陷

部分酒馆预设要求正文放入 `<game>`，运行时原先又强制要求输出 `## maintext`。模型可能先写完整正文，再补一段短的 Markdown 正文；旧解析器只读取标题后方内容，忽略第一个标题之前已保存的长正文。它也会用后一个 maintext 覆盖前一个正文区段。

例子：

```text
<content><game><p>完整的长正文……</p></game></content>
## maintext
较短的重复概述。
## sum
一句话总结。
```

现在 `TavernCore.parseOutput` 在流式预览和最终显示中使用同一规则：

- 识别 `<game>`、`<content>`、`<maintext>`，嵌套容器只提取一次，多个独立容器按顺序保留。
- 存在明确正文容器时，显示其中的完整正文；后方为兼容而生成的短 maintext 不替换它。
- 没有容器时，保留 Markdown 正文前的叙事及所有 maintext 区段，继续支持纯文本和自定义章节。
- 段落、引语、换行及语义 HTML 转为安全文本自然段，以 textContent 呈现，不执行模型提供的 HTML 或脚本。
- 原始消息、历史、存档和状态更新流程保持原格式；修复不需要重演或重新生成已保存回复。

运行时说明也已调整：正文遵循当前启用预设的容器，默认使用 `## maintext`；每轮只输出一份完整正文。字数要求按可见正文计算，不把思考、选项、总结或后台元数据计入。

## 如何排查字数与预设

先确认当前会话绑定的预设，再通过“预览实际请求”核对启用条目是否真正进入发送体，以及实际 maxOutputTokens/max_tokens 和思考配置。请求预览是下次请求的组装结果；已有请求应使用内存中的最近实际请求记录核对，不能混称。

不要把可见文本偏短直接当成预设未发送的证据。需要比较完整回复与显示结果，区分生成长度和显示解析问题。当前修复已在原有保存回复上验证：原界面约 94 个非空白字符，修复后为 1890 个非空白字符、其中 1731 个汉字，21 个自然段；没有新增模型请求。

## 兼容边界

这不是完整的 SillyTavern 运行环境。容器兼容不等于所有宏、脚本或 HTML 组件都已支持。`{{setvar::...}}`、`{{getvar::...}}` 等尚未执行的宏仍由兼容报告提示；独立 HTML 组件样式、脚本和任意导入扩展不能据此视为已适配。导入／导出继续保留受支持字段及安全的未知字段。

验证：`node --test tests/tavern-output.test.cjs tests/tavern-core.test.cjs tests/tavern-upstore-display.test.cjs tests/tavern-scroll.test.cjs tests/tavern-options.test.cjs`。测试使用合成内容，覆盖长正文恢复、混合和嵌套格式、重复章节、任意分块、原消息不变、更新块隐藏和安全文本显示。
