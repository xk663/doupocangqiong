# 酒馆游玩衔接修订（2026-10-29）

## 预设与角色选择

开启新人生读取当前启用的预设 ID，优先使用酒馆设置，兼容本地保存的预设选择；ID 已失效时才回退到第一份可用预设。开局会话绑定实际使用的 ID。

普通新建对话继续沿用当前会话的角色快照。角色卡编辑器提供「保存并用此角色新开对话」：先保存编辑/导入的卡，再明确以所选卡创建独立会话。导入后打开该编辑器，不偷偷替换当前会话的人设。新会话及活动会话设置通过同一数据库事务写入，失败不激活不存在的会话。

## 重演保护

`replay-guard.js` 为每轮可重试/已完成状态生成一致性标记，覆盖当前人生的角色、时间、世界事实、地图位置、经济、任务、驻地运行态，以及同人生会话的消息、变量、记忆、待核对技能和战斗状态。设置与界面选择不参与比较，因此可换模型或预设重演。

重演前比较该回合的标记与当前进度。若其后发生角色纠错、地图行动、其他会话发展等变化，阻止模型请求及状态覆盖。生成期间再次校验状态，防止迟到回复覆盖新进度。未变化的最新回合、刷新后恢复的最新回合，以及首次请求失败后重试均受支持。

这是一致性校验，不是完整事件日志或多人并发锁；它不会把不同会话自动合并为可独立回溯的剧情分支。回溯仍是显式恢复操作。旧回合缺少校验标记时采取保守处理：不能直接重演，可发送新消息继续，或先明确回溯并从对应时间点继续。

## 验证与边界

`node --test tests/*.test.cjs`：311 项通过，包含实际开局、角色导入与新建、真实回合函数的模拟网络请求、重演拦截、失败重试和刷新恢复。未调用付费模型，未推送或部署。

本轮只修复上述三项。角色卡内置世界书、`{{original}}`、原消息末尾补写，以及游戏附加提示词的独立配置仍是待实现兼容项，不宣称完整兼容 SillyTavern。
