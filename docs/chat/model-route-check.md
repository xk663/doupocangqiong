# 模型路由检测

## 查看一轮回复

点击助手回复下的「路由检测」即可查看发送的模型名、接口报告的模型名、字段来源和核对结果。此步骤直接使用该轮 JSON 或 SSE 响应。历史回复沿用当时保存的核对记录。

前端移植了 Sub2API 的 `backend/internal/service/upstream_response_model.go` 中的模型观察规则。OpenAI 兼容响应依次读取 `response.model`、`model`，优先使用终止事件的声明，其余情况保留首次声明。Gemini 从外到内读取最多两层 `response` 包装的 `modelVersion`，采用最后一次有效声明。同一优先级的声明发生变化时，面板会标出冲突。对比时忽略大小写，并兼容 Sub2API 列出的 Grok 4.5、4.6、4.7 的 latest/build 别名。

本项目也识别已有反代的明确模型字段、模型响应头和 `models/` 前缀。显式上游字段优先于可能回填请求名的 `model`。如果服务隐藏真实路由，前端只能显示它披露的标识。新回复不再采集文风统计或要求建立对照库。

## 主动测试渠道

在「API 设置」的接口卡片点击「路由测试」，或从回复下的「路由检测」进入，点击「开始测试」。每次发送一道算术题，最多请求 50 个输出 token，可能按渠道计费。打开面板和正常聊天均不会自动发送测试题。通过历史消息启动时，工具沿用该轮实际选择的模型，并检查原接口 ID、协议、地址摘要及同源转发设置。找不到匹配的启用配置时，只能查看历史记录。

测试规则来自 Sub2API 的 `backend/internal/service/channel_monitor_challenge.go`、`channel_monitor_checker.go` 和 `channel_monitor_const.go`。渠道监控 V1 从 1 至 50 随机取两个整数做加法或非负减法，并在回答的整数中匹配预期值。答对且耗时低于 6 秒为通过，达到 6 秒显示响应较慢。答案不匹配、HTTP 错误和 45 秒超时分别显示。测试本身的模型声明单独展示。算术题能验证当前渠道回答简单请求的能力，不能识别隐藏模型或重建历史路由。

OpenAI 兼容和 Gemini 原生请求使用项目配置的地址、鉴权及 Gemini 本机转发。Ollama 和 KoboldCPP 使用本项目已有的原生请求格式。测试问题独立于游戏聊天，关闭面板会中止本机等待。测试结果只显示在面板内。
