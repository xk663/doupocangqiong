# 流式请求失败时保留原因与响应

模型服务返回 HTTP 成功、完整接收流、完成回复处理、持久化剧情是不同步骤。单看反代的成功标记，不能确认前端已完成整轮提交。

## 前端行为

- 出错后在当前聊天中保留失败卡片，显示阶段：组装请求、接收模型响应、处理回复或保存回复。
- 已接收内容可在卡片中展开查看，包括单个 Gemini 响应携带正文但以 MAX_TOKENS 等原因被拒绝提交的情形。公开思考字段不会混入这里。
- 这些内容是未完成响应，不加入正式消息历史，不参与后续提示词，不自动更新角色、物品、概要或任务。
- 失败副本单独保存在当前标签页 sessionStorage 的 `doupo_failed_turns_v1`，最多五个会话、每份最多二十万字符；浏览器不允许写入时仅保留在当前页面，并显示提醒。当前会话重试成功或重置后清除相应记录。
- 错误说明及响应中的已配置密钥会脱敏；不记录请求头、API 配置或 Secret。卡片用 textContent 呈现响应，模型提供的标签和脚本不会执行。
- 不自动重试、续写或发起额外模型调用。用户手动重演仍会重新请求模型。

Gemini 流结束仍要求 STOP 和有效正文。缺少 STOP 的错误明确显示已收到的字符数；MAX_TOKENS、拒绝处理、空正文或损坏的数据仍不能当作成功回合提交。

## 本次排查的限制

原来的错误只有短暂弹窗，没有持久记录，流式预览也会在失败收尾时被移除。对于安装本改动之前已经失败的请求，不能凭新增机制还原原始错误或响应。

本次没有重新调用真实模型。读取反代控制台的 Windows 浏览器自动化被浏览器安全策略中止，未继续通过该方式查看。失败的具体原因尚未得到证实，不能把正常完成校验直接放宽为有文本就成功。
