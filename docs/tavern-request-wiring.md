# 世界书、预设、角色名与正则的请求链路

2026-10-25，对照 SillyTavern 官方文档与 release 分支 world-info.js 核查。

## 核心结论

模型不会读取浏览器设置页或 IndexedDB。前端必须在每次请求前，把相关条目正文组成 messages 再交给 API。导入、启用、命中和最终进入请求是四个不同状态。当前浏览器中的“斗破苍穹世界观”261条目处于未启用状态，实际预览因此显示0本参与、0条正文。

## 本项目实现

1. `prepareTavernRequest` 是聊天发送和本地预览的共同入口。
2. `TavernWiring.resolve` 合并全局世界书选择与会话绑定，按ID去重，忽略关闭的书和失效ID。预设优先使用会话选择，再取设置中的活跃预设，最后回退第一项。
3. 当前输入与历史副本先应用Prompt层正则；原始聊天记录保留。扫描默认最近6条历史及当前输入，可调整为0–100条。
4. 常驻条目无需关键词；普通条目按主关键词与启用的副关键词逻辑判断。递归默认最多3层，可设置0–8层。预算默认8192估算token，可调0–32768。按优先级占用预算，禁用、未命中与超预算分别记录。
5. 预设控制世界书与角色定义前后、深度插入以及消息角色。最终在保留回复空间后裁剪旧历史；固定内容仍超限时明确报错。
6. 玩家称呼与 `{{user}}` 优先取 `GameState.player.name`，旧会话的“玩家”或别名不再盖过创角姓名。移除两个设置入口的用户名输入；旧存档字段不删除。
7. 深度插入世界书也解析玩家、角色及地点宏。普通预设块保持原有宏、角色与顺序逻辑。
8. 世界书管理增加本地测试输入、扫描参数、请求预览。显示未启用书、条目命中原因和最终messages。最近实际请求也可在当前会话内查看，仅保存在内存中，不包含API配置对象，不写入自动存档或云备份。
9. 预览不会发送网络请求、生成骰池、增加聊天回合。实际请求会加入本轮骰池，故预览并非未来请求字节完全相同的承诺。
10. 正则支持本项目显示／Prompt／两层、启用开关、显式flags与本地测试。显示规则只改渲染；Prompt规则只改发出的用户输入与历史副本，不改系统规则、变量结算或原始记录。`{{match}}` 与捕获组可用于替换。

## 设置编辑及保存

世界书条目编辑器补上条目启用、优先级、副关键词与四种逻辑。编辑时只转义显示副本，不把HTML实体写回原始条目。世界书选择通过IndexedDB事务同时保存全局设置与当前会话，保存失败不留下半生效选择。正则保存前校验表达式；浏览器存储失败保留旧规则。

## 与 SillyTavern 的边界

本项目借鉴动态词典、预设块、深度注入和正则处理链，但保留纯静态前端及自身数据格式。尚未实现完整的概率激活、互斥组、sticky/cooldown/delay、向量检索、所有宏、角色/Persona世界书绑定界面、复杂匹配选项及全部ST导入字段。SillyTavern的正则数组placement不能直接当作本项目0/1/2层。不要宣称完整兼容，也不要把261条全文默认塞入每次请求。

## 验证

`node --test tests/*.test.cjs`：106项通过。新增实际聊天链路的模拟请求测试，核对全局世界书正文、真实角色名、Prompt正则进入发送消息且当前输入只出现一次；同时覆盖禁用预设、预算、扫描范围、递归宏、失效表达式及保存失败回滚。

浏览器验证世界书未启用的诊断、玩家姓名显示、正则本地清理测试、设置及诊断弹窗；无控制台错误。未配置API、未调用真实付费模型，不能据此保证特定服务商一定遵循世界书内容。
