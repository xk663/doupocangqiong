# 内置战斗

在正式入口 `index.html` 的“偏好设置 → 战斗”开启。旧存档默认关闭；不改变原来的聊天模式。设置包括赛跑动画、动画播放速度、敌方意图，以及战后自动发送战报。播放速度不会改变结算。

## 使用流程

1. 正文模型按注入协议输出有证据的 `battle_updates`，前端在当前会话显示遭遇入口。
2. 选择进入战斗或留在正文。只支持一对一；必须明确当前对手、境界及针对玩家的冲突。
3. 战斗内普通攻击、技能、防御、跳过行动、认输都在本地计算，每次行动先写入 IndexedDB，再播放结果。界面可收起，也可刷新后继续。
4. 战斗结束先保存结算与玩家资源比例，再按设置自动或手动发送战报。API 失败后从同一条用户战报重试，不重复追加输入、不重复结算。

## 技能与数值边界

- 不使用试玩版的示例技能。只有本轮正文明确说玩家学会、掌握、领悟或创出技能且附带对应证据时，才收录到 `player.battleSkills`。同时补充到已有法门列表。
- 不依据名称猜测旧技能的威力；旧存档没有证据和战斗记录的技能需后续正文明确确认。当前支持普通伤害、灼烧、减速、加速、打断蓄力五种组件。
- 品阶和效果转换为本地倍率、斗气消耗、冷却；模型不能直接指定任意伤害数值。本版数值为游戏规则，不宣称原著固定数值。
- 玩家使用实际姓名、境界和基础属性。境界基础倍率为 1.58 的阶段次方，同阶每超过一星增加 4.5% 的倍率；速度按阶段和速度/敏捷属性换算。纳入已装备物品的明确数值加成，暂不支持多人阵容。
- 气血和斗气比例保存在 `player.combatVitals`，随下一场继承。正文明确说明对应资源完全恢复并附证据后才恢复；普通休息不自动回满。
- 人形敌人使用通用蒙面形象，魔兽用爪印示意；玩家立绘按角色性别复用现有素材，不代表当前角色必须叫萧炎或薰儿。

## 存档与接入点

- `chat.battle`：遭遇来源消息、状态、引擎状态、行动修订号、战报用户楼层 ID。
- 玩家资源和最终战斗状态在一个 IndexedDB 事务内写入。存储失败时不推进状态；同源其他页面已更新同场战斗时拒绝覆盖。
- 全量存档包含会话战斗、玩家技能/资源和战斗偏好；回溯快照也记录对应战斗状态。
- 战斗或待发送战报期间阻止正文继续推演、切换会话和并发修改角色；完整读档和回溯可以恢复之前的状态。
- iframe 仅渲染战斗界面、提交行动意图；主页面校验来源窗口、来源域、会话令牌与行动修订号，负责结算和持久化。iframe 不读取正式存档、不持有 API 配置、不发网络模型请求。
- 开启本地战斗时，不注入旧自动战斗推演协议；旧空 `<battle>` 触发协议停止注入。原自定义协议文本保留在设置中。

## 验证

`node --test tests/battle-integration.test.cjs` 覆盖技能证据、NPC 冲突排除、协议互斥、状态恢复、资源结算、正文事务回滚、战报失败重试与幂等性。

`tests/fixtures/battle.html` 提供独立测试存档、模拟正文、模拟保存/续写失败和模拟 API 计数，便于检查实际嵌入界面。它不访问正式存档、不连接模型。

真实服务的元数据遵从程度与战斗平衡需要后续实际游玩验证；本次验证不消耗付费 API。

## 第二阶段结构补充

战斗规则现由 `assets/js/battle-rules.js` 集中管理。角色境界、星级、基础属性、装备加成、行为类型和战斗状态共同生成战斗面板，并保留速度、攻击、防御等数值构成说明。敌人行为先支持谨慎型、猛攻型和灵巧型；敌方技能只有正文记录后才可进入战斗。

每场战斗保存种子和随机序号，行动可以从同一存档继续复现。战斗结算会写入玩家 `stateChanges`，并将确认结果接入当前会话的 `memoryTable` 与 `openWorldState`。会话的 `playerState` 作为历史副本保留，切换聊天不会覆盖当前人生的角色状态；不同人生需通过完整存档恢复。列表标记战斗中和待发送战报。

状态归属、历史技能补录、装备字段与随机数修订详见 [结构完整性修订](structure-integrity.md)。
