# 存档管理

新版仍读取原有`doupo_saves`存档数组，无需手动迁移。完整存档继续包含玩家、大世界、故事任务、人物动态、聊天、世界书、预设及回溯快照；旧版角色存档会明确标注没有聊天历史。

- 支持按名称、角色、实力、地点或备注搜索；按更新日期或名称排序；可置顶，并筛选恢复点、置顶及回收站。
- 新建时可指定名称与备注；卡片支持改名备注、导出、覆盖和恢复上一版。覆盖只保留一份上一版，不递归保留所有旧版本；新建独立存档可长期保留关键分支。
- 普通删除只移入回收站，可以恢复。永久删除须先进入回收站，并单独确认，无法撤销。
- 读取先确认，并在当前有角色时先保存读档恢复点。只替换未置顶且未进回收站的上一次自动恢复点，置顶可保留旧恢复点；不自动删除手动存档。恢复点写入失败则不继续读档，恢复过程失败则保留已写入的恢复点。
- 从标题页读档会直接进入该人生。推演、地图移动、人物档案写入期间禁止保存或恢复，避免截取中间状态。
- 导入最多20MB的单个JSON，校验后保存为新的独立副本，不立即加载，也不覆盖同名或同ID存档。取消、解析失败、存储写入失败不提示导入成功。
- 存档库本身损坏或不是数组时，停止写入并显示错误，不把损坏的数据当作空库重新覆盖。
- 存档及上一版导出均剔除密钥。恢复时，仅对地址及接口类型一致的美人榜独立API保留当前浏览器的Key；外来存档不能注入或带走密钥。

存档库仍使用浏览器本地存储，卡片显示的是估算占用，不表示浏览器配额。聊天很多时应定期导出JSON；回收站和上一版同样占用空间。清理浏览器站点数据会丢失本机存档，导出文件需自行保管，且其中仍包含私人聊天与角色内容。

回归测试：`node --test tests/*.test.cjs`。隔离界面验证：`tests/fixtures/save-manager.html`，使用单独存储键，不读写主游戏存档库。
