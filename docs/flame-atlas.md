# 异火榜交互与正文档案

异火榜使用左侧名录、右侧详情；手机点选名录进入详情，可以返回。提供名称搜索、原著/项目补充、本次人生有记录、已收服记录过滤。

23 种异火均使用内置 image_gen 分别生成的独立背景，位于 `assets/images/flames/flame-01.png` 至 `flame-23.png`。实际尺寸1536×1024。提示词与文件对应关系见 `docs/flame-art-prompts.json`。原著资料不足的形象采用克制的原创视觉演绎，18、20、21按用户补充设定绘制；图像不作为新的能力设定。

只加载当前所选背景。图片铺满上方展示区，标题、简介仍由 HTML 文本叠放；左侧渐变维持可读性。图片加载失败时回退 CSS 焰形；降低动态效果偏好时停止回退动画。

原著介绍和参考持有者独立展示，不作为当前人生事实。三种项目补充异火保留来源标识。融合关系仅列已有明确资料，不推算通用克制或成功率。

`player.flameChronicle` 保存此生火迹、进度、当前持有者与线索可信度，自动随完整存档、当前进度与回溯快照保存。新人生清除此字段。旧人生不会根据原著介绍自动补全收服记录。

主聊天可输出 `flame_updates` 元数据，不额外调用模型。每条记录须有本轮可见正文的逐字证据，并包含对应异火全名；无效元数据隐藏，正文保留。传闻、历史叙述及他人持有不能授予玩家收服状态。收服还需正文明确成功及玩家姓名匹配，保守校验可能漏记不够明确的表述。记录只是事实档案，不直接改变能力或资源。

事件按回合与证据去重，和助手消息在同一事务提交。重演从回合前快照重新生成；持久化失败不更新内存。失败、失去、融合与情报推翻也可留在经历中。当前进度与已记录持有者分别展示，避免推断本体、子火或不同火种为同一实例。

地图按钮只接受已发现节点，并要求证据含地点全名；只查看节点，不自动走路或揭示隐藏地点。模糊地点保留为区域线索。询问、调查、筹备收服和研究融合写入聊天草稿，不自动发送，已有草稿不会被覆盖。

自动化测试使用模拟回复；`tests/fixtures/flames.html` 采用合成记录与地图替身，不读取真实存档、不调用 API。真实地图渲染仍复用既有 PixiJS 地图。
